# Безопасность Polygloto

Модель угроз, как закрыт каждый риск и чем это проверено, известные
остаточные риски и чек-лист перед запуском.

Проект работает на **бесплатном тарифе Spark**: Cloud Functions и Storage не
используются, серверного кода нет. Единственная серверная защита — Firestore
Security Rules (`firestore.rules`). Всё, что раньше делали функции, теперь
делает клиент, а правила проверяют каждую запись. Ниже описано, как это
устроено и чего такой подход не покрывает.

## Принципы

- **По умолчанию всё запрещено.** В `firestore.rules` доступ есть только там,
  где он явно описан. Неизвестные коллекции и подколлекции закрыты.
- **Правила не доверяют клиенту.** Служебные поля (роль, бан, статус
  модерации, счётчики, отметки времени) клиент может писать только в строго
  описанных переходах, и правила проверяют каждое значение.
- **Согласованность нескольких документов — через `getAfter()`.** Когда одно
  действие меняет несколько документов (голос и счётчики, курс и отметка
  rate limit, одобрение и снимок), клиент пишет их одним пакетом или
  транзакцией, а правило каждого документа смотрит, каким будет соседний
  после той же записи. Записать только «удобную» половину нельзя.
- **Черновик и публикация разделены физически.** Читатели видят только
  `publicCourses/{id}`. Писать туда контент может только админ, и его браузер
  при одобрении пропускает черновик через очистку `shared/publicSnapshot.js`.
- **Контент — данные, а не HTML.** Уроки хранятся JSON-блоками и рендерятся
  React-компонентами; `dangerouslySetInnerHTML` в проекте нет.
- **Подтверждение почты** проверяется только по `request.auth.token.email_verified`.

## Модель угроз

| Угроза | Защита | Проверка |
|---|---|---|
| Выдать себе роль `admin` | При создании профиля разрешены только `reader`/`user`; позже роль меняется только `reader → user` | rules: users |
| Стать автором без подтверждённой почты | `role: "user"` при создании и переход `reader → user` требуют `email_verified` в токене | rules: users |
| Снять с себя бан | `banned` меняет только админ, не себе и не другому админу; при создании профиля `banned: false` | rules: users |
| Прочитать чужой черновик | `courses/**` читают только автор и админ; `list` требует фильтр по своему `authorId` | rules: courses |
| Опубликовать курс в обход модерации | Переходы в `published`/`rejected` — только админ; `published` только вместе со свежим снимком (`approvedAt == request.time`); контент `publicCourses` пишет только админ | rules: courses, public |
| Отправить на проверку без подтверждённой почты | Переход `draft → pending_review` требует `email_verified` в токене | rules, e2e 8 |
| Подменить контент после отправки | На проверке контент заморожен; одобрение завершается транзакцией, которая проверяет, что курс не переотправили | e2e 8 |
| XSS через контент курса | JSON-блоки, очистка при публикации, рендер без HTML | unit: content |
| Сломать страницу модератора испорченным черновиком | Страница проверки рендерит черновик через ту же очистку, что и публикация (`loadCourseContent`) | этап 13 |
| Накрутка лайков | Одна оценка на пользователя (`ratings/{uid}`); правило требует, чтобы счётчики в той же записи изменились ровно на разницу голосов; менять счётчики без своей оценки нельзя; автор не голосует за свой курс | rules: activity; e2e 9 |
| Испортить счётчики, сбросив их | Не-админ может менять в `publicCourses` только `likesCount`/`dislikesCount`/`score` и только вместе со своей оценкой, с проверкой дельты | rules: public, activity |
| Спам комментариями | Не чаще раза в 15 с: комментарий создаётся только вместе с отметкой в `rateLimits/{uid}`, а отметку нельзя поставить, пока не прошёл лимит | rules: users, activity; e2e 9 |
| Спам курсами | То же, не чаще раза в 30 с | rules: courses |
| Комментарий от чужого имени | `authorId` — свой uid, `authorName` — ровно текущее имя из профиля | rules: activity |
| Реакции от чужого имени и на несуществующие цели | id реакции = `{uid}_{тип}_{id}`, эмодзи из фиксированного набора, цель должна существовать | rules: activity |
| Удалить чужое | Курс — автор или админ; комментарий — его автор, автор курса или админ; реакции и оценки — только свои (и «сироты» удалённого курса или комментария) | rules |
| Переполнение базы | Лимиты длины и числа элементов в правилах (`LIMITS` в `shared/schema.js`) | rules |
| Чужой или внешний URL аватара (трекинг, подмена) | `photoURL` — только `data:image/jpeg;base64,…` до 40 000 символов; внешние ссылки запрещены | rules: users; e2e 11 |
| Вредоносный файл вместо аватара (SVG/HTML) | Принимается только JPEG в data URL; клиент перекодирует картинку в JPEG 160×160 | rules: users; e2e 11 |
| Утечка email | Email не хранится в Firestore; публичный профиль содержит только имя, фото и «о себе» | data-model |
| Кликджекинг, внедрение скриптов | Hosting отдаёт CSP (`script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`. CSP действует на всех страницах сайта, кроме служебных страниц Firebase `/__/…` (подтверждение почты, сброс пароля): они не наши и работают на встроенных скриптах Firebase. Встроенных скриптов в самом сайте нет, это проверяет `src/csp.test.js` | этап 13, правки 3 |

## История аудита

Финальный аудит этапа 13 проводился для версии с Cloud Functions. Его выводы,
которые остаются в силе: страница модератора рендерит черновик через ту же
очистку, что и публикация; бан запрещает любые записи; включены заголовки
безопасности хостинга. Исправления, касавшиеся функций и Storage (path
injection в callable, число файлов в папке аватара, пересчёт счётчиков
триггерами), потеряли смысл вместе с самими функциями.

При переходе на Spark правила переписаны и покрыты тестами заново (83 теста
в `tests/rules/`), см. раздел «Переход на Spark» в `docs/stage-reports.md`.

## Известные остаточные риски

- **Админ — доверенный клиент.** Очистку снимка выполняет браузер админа.
  Правила проверяют, что пишет именно админ, но не содержимое снимка
  (правила не умеют обходить вложенные блоки). Давайте роль `admin` только
  доверенным людям. Рендер всё равно не использует HTML, так что XSS это не
  открывает.
- **Одобрение не атомарно.** Разделы снимка пишутся пакетами по 400 записей,
  а финальная транзакция проверяет, что курс всё ещё на проверке. Если автор
  отзовёт курс прямо во время одобрения, транзакция откажет, но уже
  записанные разделы останутся. Для уже опубликованного курса читатели могут
  увидеть новые разделы при старом оглавлении до следующего одобрения.
- **Каскадное удаление выполняет клиент.** Если вкладку закроют посреди
  удаления курса, часть подколлекций останется; повторное удаление
  продолжит с того же места. Оценки удалённого курса приватны и остаются
  «сиротами».
- **Счётчики языков в каталоге** обновляются только при одобрении. После
  удаления опубликованного курса автором число курсов в фильтре может быть
  завышено до следующего одобрения курса на этом языке.
- **Роль и бан видны публично** в `users/{uid}`: правила Firestore не умеют
  скрывать отдельные поля. Это не личные данные.
- **Частая смена оценки или реакции** не ограничена по времени. Накрутить
  счётчик нельзя, но можно тратить квоту чтения и записи Spark. Защита на
  уровне платформы — App Check (см. чек-лист).
- **Данные удалённого аккаунта.** Без функций нет триггера на удаление
  пользователя Auth: профиль и курсы остаются, их удаляет админ вручную.
- **Имя автора в старых комментариях** не меняется при смене имени: это
  снимок на момент написания.
- **Лимиты тарифа Spark** (50 000 чтений и 20 000 записей в сутки): при
  превышении Firestore до конца суток возвращает ошибку квоты. Для
  небольшой аудитории этого хватает.

## Версия 2: новые риски и решения

Функции v2 сделаны в тех же рамках: тариф Spark, без Cloud Functions и
Storage, без составных индексов. Каждая новая коллекция покрыта тестами
правил (`tests/rules/`: srs, audio, taskStats, gamification, follows,
coauthors, lessonComments).

- **Аудио без Storage.** Файлы хранятся data URL в документах
  `courses/{id}/audio` (до ~350 КБ на файл, только `audio/*` в base64,
  проверка формата в правилах, не чаще раза в 5 с). Это расходует квоту
  чтения Firestore: файл загружается, только когда читатель нажал «▶».
  Внешние ссылки — только https на `upload.wikimedia.org` (проверяют и
  правила, и CSP `media-src`). Содержимое файла (что это действительно
  звук) правила не проверяют, но браузер проигрывает его только как аудио.
- **SRS-карточки приватны** (`users/{uid}/srsCards`): читает и пишет только
  владелец; интервалы и даты правила проверяют на допустимые значения.
- **Статистика заданий только агрегированная.** Автор и соавторы видят
  суммы попыток и ошибок, без имён; процент показывается от 5 ответов.
  Счётчик растёт ровно на 1 и только вместе с созданием личной отметки
  первой попытки, поэтому один читатель не может накрутить статистику.
- **Задания проверяются в браузере.** Правильные ответы лежат в
  опубликованном уроке, их можно подсмотреть. Это влияет только на очки
  самого ученика: максимум 10 очков за задание и только один раз.
- **Очки и серия** пересчитываются правилами из события, которое их
  оправдывает (первая попытка задания, первое прохождение урока,
  засчитанное повторение). Накрутить их повтором действия нельзя. Мини-игры
  очков не дают: правила не могут проверить результат игры.
- **Отметка «курс пройден» проверяется упрощённо** (есть прохождение
  первого и последнего уроков), потому что правила не умеют обходить
  список уроков. Влияет только на значки самого пользователя.
- **Сутки по UTC.** Серия и задания дня считаются по UTC: так правила и все
  пользователи считают одинаково. Новый день начинается в 3:00 по Москве.
- **Подписки публичны.** Кто на кого подписан, видят все (так считается
  число подписчиков). Подписаться можно только от своего имени.
- **Соавторы** правят черновик и отправляют его на проверку наравне с
  автором, но не удаляют курс и не меняют список соавторов. Публикует
  по-прежнему только модератор. Существование пользователя в списке правила
  не проверяют; несуществующий id ни на что не влияет.
- **Импорт курса** проходит ту же очистку, что и редактор, и создаёт обычный
  черновик с теми же лимитами; аудио из файла загружается с паузами, чтобы
  уложиться в лимит частоты.

## Чек-лист перед запуском

- [ ] **App Check** (reCAPTCHA v3 или Enterprise) для Firestore, с
      принудительным режимом после проверки на проде: отсекает скрипты,
      которые ходят в API мимо сайта. Доступен на Spark.
- [ ] Authentication → Settings: **Email enumeration protection** включена;
      в **Authorized domains** только ваш домен и `localhost`.
- [ ] Google Cloud → Credentials: для **API key** веб-приложения ограничения
      по HTTP referrer (ваш домен).
- [ ] Первый администратор назначен вручную: Firestore → `users/{uid}` →
      `role: "admin"`.
- [ ] Правила и индексы задеплоены: `firebase deploy --only firestore:rules,firestore:indexes`.
- [ ] Если сайт будет обращаться к другим доменам, дополните CSP в `firebase.json`.
- [ ] Периодически выгружайте данные: на Spark нет автоматических бэкапов
      Firestore, поэтому важные курсы стоит сохранять скриптом на Admin SDK.
