# Безопасность Polygloto

Итог финального аудита (этап 13): модель угроз, как закрыт каждый риск и чем
это проверено, известные остаточные риски и чек-лист перед запуском.

## Принципы

- **По умолчанию всё запрещено.** В `firestore.rules` и `storage.rules` доступ
  есть только там, где он явно описан. Неизвестные коллекции, подколлекции и
  пути Storage закрыты.
- **Сервер не доверяет клиенту.** Роль, бан, счётчики, статусы модерации,
  опубликованный снимок и rate limit пишет только сервер (Cloud Functions
  через Admin SDK). Правила запрещают клиенту эти поля.
- **Черновик и публикация разделены физически.** Читатели видят только
  `publicCourses/{id}`, а его содержимое при одобрении проходит серверную
  очистку (`shared/publicSnapshot.js`).
- **Контент — данные, а не HTML.** Уроки хранятся JSON-блоками и рендерятся
  React-компонентами; `dangerouslySetInnerHTML` в проекте нет.
- **Подтверждение почты** проверяется только по `request.auth.token.email_verified`
  (в правилах) и `auth.token.email_verified` (в функциях).

## Модель угроз

| Угроза | Защита | Проверка |
|---|---|---|
| Выдать себе роль `admin`/`user` | `users` создаёт только триггер; при обновлении клиенту доступны только `displayName`, `bio`, `photoURL` | rules: users |
| Снять с себя бан, накрутить `commentsCount` | То же: служебные поля клиенту недоступны | rules: users |
| Прочитать чужой черновик | `courses/**` читают только автор и админ; `list` требует фильтр по своему `authorId` | rules: courses |
| Опубликовать курс в обход модерации | Клиенту запрещены статусы `published` и `rejected`, а `publicCourses` пишет только функция | rules: courses, public |
| Отправить на проверку без подтверждённой почты | Переход `draft → pending_review` требует `email_verified` в токене | rules, e2e 8 |
| Подменить контент после одобрения | На проверке контент заморожен; одобрение — транзакция с проверкой, что курс не переотправили | functions: moderation |
| XSS через контент курса | JSON-блоки, строгая очистка на сервере при публикации, рендер без HTML | unit: content; functions: moderation |
| Сломать страницу модератора испорченным черновиком | Страница проверки рендерит черновик через ту же очистку, что и публикация (`loadCourseContent`) | этап 13 |
| Накрутка лайков | Одна оценка на пользователя (`ratings/{uid}`); счётчики пересчитывает триггер через `count()`; автор не голосует за свой курс | rules: activity; functions: activity |
| Спам комментариями | Только callable `addComment`: проверка публикации и бана, длина, не чаще раза в 15 с | functions: activity; e2e 9 |
| Спам курсами | Только callable `createCourse`: не чаще раза в 30 с | functions: courses |
| Реакции от чужого имени и на несуществующие цели | id реакции = `{uid}_{тип}_{id}`, эмодзи из фиксированного набора, цель должна существовать | rules: activity |
| Удалить чужое | Курс — автор или админ; комментарий — его автор, автор курса или админ; реакции и оценки — только свои | rules |
| Путь вместо id в callable (`c1/lessons/l1`) | `requireDocId` во всех callable, принимающих id | functions: activity |
| Переполнение базы | Лимиты длины и числа элементов в правилах и функциях (`LIMITS` в `shared/schema.js`) | rules, functions |
| Чужой или внешний URL аватара (трекинг, подмена) | `photoURL` — только файл из собственной папки `avatars/{uid}/` | rules: users |
| Вредоносный файл вместо аватара (SVG/HTML) | Storage: только JPEG/PNG/WebP до 2 МиБ с безопасным именем; клиент перекодирует в JPEG 256×256 | rules: storage; e2e 11 |
| Забивание Storage | Загружать может только незаблокированный владелец; триггер `onAvatarUploaded` оставляет в папке 3 последних файла | rules: storage; functions: profile |
| Утечка email | Email не хранится в Firestore; публичный профиль содержит только имя, фото, «о себе» и счётчики | data-model |
| Личные данные после удаления аккаунта | `onUserDeleted` удаляет профиль, rate limit и аватары | functions: profile |
| Порча счётчиков при повторной доставке событий | Триггеры пересчитывают значения запросами `count()`, а не прибавляют ±1 | functions |
| Кликджекинг, внедрение скриптов | Hosting отдаёт CSP (`script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff` | этап 13: собранное приложение без нарушений CSP |

## Что исправлено при аудите

1. **Path injection в callable.** Admin SDK принимает в `doc()` путь из
   нескольких сегментов. Поэтому `addComment({ courseId: "c1/lessons/l1" })`
   прошёл бы проверку «курс опубликован» (такой документ существует) и
   записал бы комментарий и счётчик во вложенный документ. Добавлен
   `requireDocId` для `addComment`, `moderateCourse` и `setUserBan`.
2. **Страница модератора рендерила сырой черновик.** Автор пишет черновик
   напрямую в Firestore и мог записать туда данные, которые роняют рендер
   (например, задание без списка вариантов). Тогда модератор не смог бы
   открыть и отклонить курс. Теперь страница проверки показывает черновик
   после той же очистки, что и при публикации: модератор видит ровно то, что
   увидят читатели. Сборка снимка вынесена в `shared/publicSnapshot.js`.
3. **Бан не распространялся на Storage.** Заблокированный пользователь мог
   загружать файлы. Правило Storage теперь читает профиль через `firestore.get()`.
4. **Неограниченное число файлов в папке аватара.** Правила не умеют считать
   файлы; ограничение держит триггер `onAvatarUploaded`.
5. **Счётчики комментариев.** `onCommentDeleted` уменьшал счётчик курса на 1
   (повторная доставка события портила бы число), а счётчик автора не
   уменьшал вовсе: удалённый модератором спам шёл в зачёт бейджа
   «Собеседник». Теперь оба счётчика пересчитываются `count()`, для этого
   добавлен индекс группы коллекций `comments.authorId`.
6. **Не было заголовков безопасности на хостинге.** Добавлены CSP и
   сопутствующие заголовки в `firebase.json`. Проверено: собранное
   приложение работает с этой политикой без нарушений.

Исправления этапов 9–11, найденные при их проверке: `photoURL` ограничен
своей папкой (раньше подходил любой файл Storage), `onUserDeleted` удаляет
аватары.

## Известные остаточные риски (осознанно приняты для v1)

- **Роль и бан видны публично** в `users/{uid}`: правила Firestore не умеют
  скрывать отдельные поля. Это не личные данные, но при желании бан можно
  вынести в закрытую коллекцию.
- **Частая смена оценки или реакции** не ограничена по времени: каждая смена —
  один документ и один запуск триггера. Накрутить счётчик нельзя, но можно
  тратить квоту. Защита на уровне платформы — App Check (см. чек-лист).
- **Курсы удалённого аккаунта** остаются опубликованными: удаление чужой
  работы без решения человека необратимо. Админ может удалить их вручную.
- **Имя автора в старых комментариях** не меняется при смене имени: это
  снимок на момент написания, как в большинстве форумов.
- **Содержимое черновика** (элементы блоков, примеры в словаре) правила
  проверяют только по размеру: правила не умеют обходить вложенные списки.
  Это безопасно, потому что черновик видят только автор и админ, а
  публикуется лишь очищенная сервером копия.

## Чек-лист перед запуском

- [ ] **App Check** (reCAPTCHA Enterprise) для Firestore, Storage и Functions,
      с принудительным режимом после проверки на проде: отсекает скрипты,
      которые ходят в API мимо сайта.
- [ ] Authentication → Settings: **Email enumeration protection** включена;
      в **Authorized domains** только ваш домен и `localhost`.
- [ ] Google Cloud → Credentials: для **API key** веб-приложения ограничения
      по HTTP referrer (ваш домен).
- [ ] Бюджет и оповещения о расходах в Google Cloud Billing.
- [ ] Первый администратор назначен вручную: Firestore → `users/{uid}` →
      `role: "admin"`.
- [ ] Если функции развёрнуты не в `europe-west1`, обновите
      `VITE_FIREBASE_FUNCTIONS_REGION`. Если сайт будет обращаться к другим
      доменам, дополните CSP в `firebase.json`.
- [ ] Резервное копирование Firestore (scheduled exports или PITR).
