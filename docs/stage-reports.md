# Отчёты по этапам

После каждого этапа: что сделано, что проверено, какие граничные случаи учтены, что дальше.

## Этап 1. Инициализация

**Сделано.** Vite + React 19 (JS, без TS), React Router 7, CSS Modules. Firebase SDK
инициализируется в одном месте — `src/services/firebase.js`, конфиг только из
`VITE_FIREBASE_*` (`.env.example`), для локальной разработки есть режим
`--mode emulators` (`.env.emulators`, demo-проект без облака). `firebase.json`
описывает Firestore, Storage, Functions (v2, регион `europe-west1`), Hosting и
эмуляторы. Схема данных — `docs/data-model.md` + константы `shared/schema.js`,
которые скрипт `scripts/sync-shared.mjs` копирует в `functions/`.

**Проверено.** `vite build` и `eslint` проходят без ошибок.

**Граничные случаи.** Нет конфига Firebase → отдельный экран с перечнем
недостающих переменных вместо падения. Правила на старте — «запрещено всё».

## Этап 2. Аутентификация

**Сделано.** Регистрация (имя, email, пароль, повтор), вход, выход,
подтверждение email, «отправить письмо повторно», «Я подтвердил»,
восстановление пароля по email, смена пароля в настройках (с повторным вводом
текущего) и альтернативно — ссылкой на привязанную почту. Функции:
`onUserCreated` (Auth-триггер, создаёт `users/{uid}` с ролью `reader`),
`onUserDeleted` (чистит профиль), `syncRole` (reader → user, только если
`auth.token.email_verified`).

**Проверено.** Интеграционные тесты функций в эмуляторе (`npm run test:functions`):
профиль создаётся с ролью reader и без email; syncRole не повышает без
подтверждения, повышает с подтверждением, не трогает admin, отклоняет аноним.

**Граничные случаи.** Неверный пароль / email занят / слабый пароль / нет сети /
слишком много попыток — понятные сообщения. Повторная отправка форм
заблокирована (`loading`). Кнопка повторной отправки письма — с таймером 60 с.
Сброс пароля не раскрывает, существует ли аккаунт. Повторная доставка
Auth-события не перезаписывает профиль (`create()`). Email не попадает в
публичный профиль (имя по умолчанию «Автор-xxxxxx»). Если триггер задержался,
регистрация всё равно успешна, имя можно поменять позже. Профиль прошлого
пользователя не «мигает» после смены аккаунта.

## Этап 3. Правила для users

**Сделано.** `firestore.rules`: профиль читается всеми (в нём нет приватных
данных), перечисление — только админ; создание/удаление клиентом запрещено;
владелец меняет только `displayName`, `bio`, `photoURL` с проверкой длины и
формата; `role`, `banned`, `commentsCount`, `createdAt` клиент не может ни
создать, ни изменить (даже админ через клиент). `rateLimits` закрыта.

**Проверено.** 16 тестов правил (`npm run test:rules`): повышение роли до admin
или user, самостоятельное снятие бана, подмена createdAt, добавление
постороннего поля, запись чужого профиля, полная перезапись `setDoc`, границы
длин (39/40/41, 500/501), аватар только с Firebase Storage (не `javascript:` и
не произвольный хост).

## Этап 4. Модель курса, черновик, автосохранение, вкладки

**Сделано.** Callable `createCourse` (валидация, rate limit «1 курс в 30 с»
через `rateLimits/{uid}` в транзакции, серверные `authorId`/`status`/служебные
поля, сразу создаётся «Урок 1»). Триггер `onCourseDeleted` удаляет
подколлекции и опубликованную копию. Правила для `courses` и подколлекций
`lessons`/`reference`: рабочую версию видит только автор и админ; контент
меняется только в статусе `draft`; клиенту разрешены лишь переходы
draft→pending_review (с `email_verified`) и pending_review/published/rejected→draft;
смена статуса и контента в одной записи запрещена. Страницы «Мои курсы»
(список со статусами, создание в модальном окне) и редактор курса со вкладками
«Самоучитель», «Справочник», «Словарь», «Настройки курса» (метаданные,
категории разметки с цветом, удаление).

Автосохранение (`useAutosave`): debounce 3 с, записи строго последовательны
(правки, пришедшие во время записи, сохраняются следующей записью), при
ошибке правки не теряются и есть кнопка «Повторить», при уходе со страницы /
переключении урока несохранённое дописывается, закрытие вкладки с
несохранёнными правками предупреждается. Контент урока грузится один раз, а не
live-подпиской, чтобы входящие снимки не затирали набираемый текст.

Черновик и публикация разделены физически: правка опубликованного курса
сначала переводит рабочую версию в `draft` (новая версия), опубликованный
снимок в `publicCourses` не трогается.

**Проверено.** 41 тест правил, 11 тестов функций (в т.ч. rate limit, запрет
для забаненного и анонима, подмена `status`/`authorId` в запросе
игнорируется, каскадное удаление). E2E-сценарий в браузере (Playwright против
эмуляторов): регистрация без подтверждения → создание черновика →
автосохранение → перезагрузка → данные на месте, добавление уроков и
разделов, клиентская валидация, отсутствие ошибок в консоли.

**Граничные случаи.** Двойной клик «Создать» (кнопка блокируется, плюс rate
limit на сервере), невалидные метаданные не отправляются, курс удалён/чужой →
понятное сообщение, одновременные сохранения нескольких полей опубликованного
курса → одна смена статуса (single-flight), правка курса на модерации
недоступна (кнопка «Отозвать и редактировать»), нет сети → Firestore
буферизует запись, индикатор показывает состояние.

## Этап 5. Редактор контента

**Сделано.** WYSIWYG-редактор на Slate (`src/components/editor/`). Модель Slate
почти совпадает с форматом хранения (`shared/content.js`), при сохранении всё
проходит через `sanitizeBlocks` — строгую очистку (только известные типы
блоков и атрибуты, цвета только из палитры, категории только существующие,
лимиты длины). Инструменты: стиль абзаца (текст / заголовок / подзаголовок),
жирный / курсив / подчёркнутый (и Ctrl+B/I/U), «снять оформление» (обычный
текст), цвет из палитры, разметка категориями курса с цветовой легендой,
таблицы (добавить/удалить строку и столбец, строка-заголовок), меню
«Вставить». Предпросмотр рендерит тот же контент компонентом читателя
`ContentRenderer` — без `dangerouslySetInnerHTML`.

Расширяемость: реестр редакторов блоков и пунктов «Вставить»
(`editorRegistry.js`), реестр рендереров для чтения (`blockRenderers.js`).
Типы `audio` и `gloss` зарезервированы под v2 (в схеме и реестре есть, при
сохранении пока отбрасываются, при чтении — заглушка).

**Проверено.** 10 юнит-тестов очистки контента (лишние атрибуты, CSS-инъекция в
цвет, чужие категории, неизвестные блоки, выравнивание таблиц, не-массив).
E2E в браузере: выделение → жирный, цвет, категория, легенда, вставка таблицы,
добавление строки, автосохранение, перезагрузка, предпросмотр с сохранённым
оформлением, ошибок в консоли нет.

**Граничные случаи.** Пустой урок (всегда есть хотя бы пустой абзац), после
таблицы всегда есть абзац, чтобы продолжить писать; вложенные/неизвестные
элементы нормализуются; изменения курсора не вызывают сохранений;
категория, удалённая в настройках, при следующем сохранении убирается из
текста; больше 400 блоков — предупреждение; пустые строки таблицы читателю не
показываются.
